# QEOS Accounting Domain Map

## 1. Chart of Accounts (COA) Structure
The COA is the backbone of the GL. It requires a rigid hierarchical structure.

### 1.1 Account Types
- **Assets (Debit Normal Balance)**
  - Current Assets (Cash, AR, Inventory)
  - Fixed Assets (Property, Plant, Equipment)
- **Liabilities (Credit Normal Balance)**
  - Current Liabilities (AP, Short-term debt, Taxes payable)
  - Long-term Liabilities (Loans)
- **Equity (Credit Normal Balance)**
  - Retained Earnings
  - Owner's Capital
- **Revenue (Credit Normal Balance)**
  - Sales, Service Income, Interest Income
- **Expense (Debit Normal Balance)**
  - COGS, Payroll, Rent, Utilities, Depreciation

### 1.2 Account Attributes
- `AccountId`: Unique Identifier.
- `Code`: Alphanumeric reference (e.g., "1000", "4100").
- `Name`: Human-readable name.
- `Type`: (Asset, Liability, Equity, Revenue, Expense).
- `IsControlAccount`: Boolean. If true, manual journals are blocked; entries must originate from a Sub-Ledger.
- `IsSystemAccount`: Boolean. Reserved for automated processes (e.g., Retained Earnings).
- `IsActive`: Boolean.

## 2. Core Domain Aggregates

### 2.1 `Account`
- Represents a node in the COA.
- Enforces natural balances and control account restrictions.

### 2.2 `Journal`
- Root aggregate for a transaction.
- Contains `JournalEntry` and a collection of `JournalLine`s.
- Enforces the `Debit = Credit` balancing rule before allowing a state transition to `Posted`.

### 2.3 `LedgerEntry`
- Immutable record generated by the Posting Engine.
- Contains the finalized, applied transaction data affecting the GL.

### 2.4 `SubLedgerRecord`
- Specific implementations for AR, AP, Inventory, etc.
- Links to external domain aggregates (e.g., `CustomerId`, `PurchaseOrderId`).

## 3. Domain Events
The accounting engine acts as both a publisher and subscriber in the QEOS Event Bus.

### 3.1 Published Events (Emitted by Accounting)
- `JournalCreated`
- `JournalPosted`
- `JournalReversed`
- `AccountCreated`
- `FiscalPeriodClosed`
- `YearEndClosed`

### 3.2 Subscribed Events (Listened to by Accounting)
- **Sales Module:** `SalesInvoicePosted`, `PaymentReceived`.
- **Purchasing Module:** `PurchaseInvoiceReceived`, `PaymentIssued`.
- **Inventory Module:** `InventoryReceived`, `InventoryDispatched`, `InventoryAdjusted`.
- **Settings Module:** `CurrencyBaseChanged` (triggers revaluation strategy), `FiscalYearCreated`.

## 4. Bounded Context Relationships
- **Settings Context:** [Upstream] Provides Currencies, Exchange Rates, Taxes, Fiscal Calendars. Accounting is a downstream consumer.
- **Operational Contexts (Sales, Purchasing, Inventory):** [Upstream] Provide economic events. Accounting translates these into financial representations.
- **Reporting Context:** [Downstream] Consumes Ledger Entries to generate Financial Statements.
